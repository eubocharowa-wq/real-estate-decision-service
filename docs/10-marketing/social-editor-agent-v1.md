## Реализация первой версии

Это отдельная редакционная роль с самодостаточным заданием ChatGPT по расписанию.
Документ можно использовать как основу инструкций Custom GPT, но создание
такого GPT в интерфейсе этим файлом не подтверждается. Роль, работа по
расписанию и доступ к API площадок — три проверяемые части.
[GPT Actions](https://developers.openai.com/api/docs/actions/introduction)
документируют вызовы внешних API из Custom GPT; [Scheduled tasks](https://learn.chatgpt.com/docs/automations)
— выполнение заданий по расписанию. Наличие любого из них не доказывает
подключение конкретного VK/TG publisher.

## Ответственность

- Редактор: темы, факты, версии VK/TG, заголовки, визуальные брифы, CTA и календарь.
- Елена: фактическая экспертная позиция, допустимые кейсы/цены и согласование пакета.
- Publisher: только согласованная версия, фиксированная площадка, очередь,
  расписание, повторы, восстановление и ссылка/ID фактической публикации.
- Модерация: сначала предложения ответов и заметки о спаме. Переписка от имени
  Елены, удаление, блокировки и доступ к личным сообщениям — отдельная политика.
- Продвижение: идеи дистрибуции и отчёт по обращениям; платные кампании требуют
  собственного утверждённого бюджета и прав. Число просмотров не заменяет результат.

Первые выпуски проходят одно пакетное согласование. После согласования
publisher сможет выпускать утверждённые записи по расписанию без повторного
ручного переноса. Изменение факта, текста, цены, ассета, цели или версии после
согласования возвращает запись на проверку. Решение об автоматическом выпуске
отдельных классов evergreen-контента оформляется позже явно, с критериями остановки.

## Приёмка издателя — отдельные PUB-VK-01 / PUB-TG-01 / PUB-OPS

1. В существующей архитектуре подготовить защищённое подключение и проверки
   действительного аккаунта/организации, группы/канала и разрешённых операций.
2. Привязать согласование к версии текста, фактам, ассетам и точному target ID.
   Агент не подставляет произвольный wall/channel ID из текста или чужого поста.
3. Постоянная очередь, блокировка конкурентной отправки, восстановление после
   рестарта, пауза по площадке. При неясном исходе — сверка, затем решение о повторе.
4. Один отдельно согласованный тест на каждой площадке, проверка видимой записи,
   авторства, текста/ассета, remote ID и ссылки; затем включение очереди.
5. Вести отдельный статус по VK и TG: частичный успех не выдавать за полный выпуск.
   Ошибка одного материала не отправляет другой текст и не открывает доступ шире.
6. Сбор комментариев/аналитики требует собственных проверенных чтений и границ
   хранения. Не обещать полноценное ведение, если доступен лишь вызов отправки.
